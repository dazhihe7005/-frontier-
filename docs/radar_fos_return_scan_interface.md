# 采空区返程补扫：雷达建模负责人工作与数据接口

**交接对象：**激光雷达／建模负责人

**对接对象：**电控／自主飞行负责人、机械负责人

**状态：**接口建议稿；话题名和阈值在双方联调时固化。

## 1. 目标和职责边界

本项目希望在去程完成采空区空间探索后，利用返程补扫表面缺口和点云质量较差的区域。这里的 FOS 指武汉大学 HFCH 工作中的 **Frontier for Object Surface（物体表面前沿）**；它用于发现尚需进一步观察的表面，不能直接等同于“点云密度低”。参考：[HFCH 论文，DOI:10.1016/j.aei.2025.103834](https://doi.org/10.1016/j.aei.2025.103834)。本交接要求是面向本项目的实现方案，不声称复现论文的未公开实现细节。

| 负责人 | 交付内容 |
|---|---|
| 雷达建模 | 配准点云与累计表面地图；FOS 提取；各表面区域的观测质量和点云密度统计；返程补扫候选视角及预期可见收益。 |
| 电控／自主飞行 | 任务阶段切换、候选视角的可达性和机体安全校验、返航余量判断、目标提交给 SUPER、异常时放弃补扫并安全返航。 |
| 机械 | 雷达安装位姿与标定结果、机体遮挡范围、机体外形和安全包络；变更安装后通知雷达及电控更新配置。 |

雷达侧输出的是**观测需求和候选观察位姿**，不是可直接执行的飞行命令。电控侧只有在实时地图、SUPER 安全走廊和返航条件均满足时才会执行。

## 2. 雷达建模侧需要完成的工作

1. **建立任务级累计地图。**仅累计本次任务启动后的有效扫描；保存表面、已知自由空间、未知空间的区别。点云和位姿统一到当前工程的 `camera_init` 坐标系，并为每次任务分配 `mission_id`、为地图更新分配 `map_revision`。任务重启或地图重定位时不得沿用旧区域坐标。
2. **提取 FOS。**在已观测表面的边界寻找仍需从新视角观察的表面区域，按连通性聚类，输出每个区域的空间范围、中心、表面法向和置信度。FOS 与空间探索的 frontier 分开标记，避免把洞内未知通道误当成待补扫表面。
3. **统计已观测表面的质量。**把墙、顶、底等表面划成固定尺度的区域，统计有效回波数、实际可评估表面面积、独立扫描次数、观测距离、入射角或观测方向分布、最近观测时间。剔除无效回波、机体自回波、明显离群点；记录滤波和降采样设置。
4. **建立健康参考并计算比值。**对相似表面、相近观测距离和入射角的健康区域求稳健参考密度。输出 `density_ratio = observed_density / reference_density`，同时输出两个原始密度值和可信度。参考值不足时标记 `REFERENCE_UNAVAILABLE`，不得把比值伪装成 0。未知而没有可估计表面的区域应标记 `UNKNOWN_SURFACE`，不能按“已观测、密度为 0”处理。
5. **融合待补扫任务。**至少区分 `FOS_GAP`（表面观察边界）、`LOW_DENSITY`（已观测但质量差）、`OCCLUDED`（遮挡）和 `HEALTHY`。同一区域可以同时具有多个原因。按区域输出优先级，保存去程与返程更新前后的统计值，便于验证补扫确有增益。
6. **生成 NBV 候选。**基于雷达有效距离、视场、表面法向和地图遮挡，给每个待补扫区域生成少量候选观察位姿。输出**机体中心目标位姿** `(x,y,z,yaw)`，而不是未经雷达到机体外参转换的雷达位姿；同时输出候选能覆盖的区域 ID、预计有效新观测量、建议扫描停留时间或通过速度。可见性和收益由雷达建模侧估计，飞行安全由电控侧复核。

密度应采用明确的空间尺度，例如点／平方米的表面区域密度；不能直接比较整帧点数，也不能让同一位置连续多帧重复命中无限抬高质量分数。具体区域尺度、健康阈值和有效独立观测条件由双方用录包标定，作为配置项交付。

## 3. 建议新增的 ROS 输出

当前工程已有 Fast-LIO2 `/cloud_registered`、`/Odometry`，并经 `task1_perception_gate` 提供任务期点云和里程计。下面是**建议新增的逻辑消息**；名称尚未在代码中实现，雷达负责人可按现有 ROS1 消息包确定最终 `.msg` 名称。

### A. `/mine_uav/model/surface_quality`：区域质量数组，必须输出

每条数组消息包含 `std_msgs/Header`（`frame_id=camera_init`）、`mission_id`、`map_revision`、地图时间戳和下列区域记录：

| 字段 | 含义与单位 |
|---|---|
| `patch_id`、`patch_type` | 本任务内稳定的区域 ID；`FOS_GAP / LOW_DENSITY / OCCLUDED / HEALTHY / UNKNOWN_SURFACE` 可用独立标志表示。 |
| `center`、`normal`、`extent` 或 `surface_voxels` | 区域中心、法向和**实际覆盖范围**；仅中心点不足以评估 NBV 可见性。位置单位米，法向为单位向量。 |
| `surface_area_m2`、`valid_hit_count`、`independent_scan_count` | 参与统计的面积、有效点数、独立观测次数。 |
| `observed_density_pt_m2`、`reference_density_pt_m2`、`density_ratio` | 区域实测密度、健康参考密度和二者比值；附上参考值的选择条件。 |
| `range_median_m`、`view_direction_count` | 观测距离及有效观察方向数，用于区分距离造成的稀疏与漏扫。 |
| `quality_confidence`、`reason_flags` | 置信度及低质量原因，包括低回波率、遮挡、入射角差、数据丢帧、位姿不可靠等。 |
| `last_observed_stamp` | 最近一次有效观测时间。 |

### B. `/mine_uav/model/nbv_candidates`：补扫候选数组，必须输出

每条数组消息携带同一 `mission_id`、`map_revision`、`header.stamp` 和：

| 字段 | 含义 |
|---|---|
| `candidate_id`、`body_pose` | 候选 ID，以及 `camera_init` 下**机体中心**的 `geometry_msgs/PoseStamped` 目标；姿态至少给出 yaw。 |
| `target_patch_ids` | 该视角预计能补到的区域 ID。 |
| `expected_new_coverage_m2`、`expected_density_gain`、`confidence` | 预计新增可见表面积、质量收益和预测置信度；允许收益为 0，不能把它当成已完成补扫。 |
| `required_view_direction`、`scan_duration_s` 或 `max_pass_speed_mps` | 需要的观察朝向、建议驻留时间或允许的通过速度。 |
| `valid_until` | 候选失效时间；地图改变或区域已补齐时更新或撤销。 |

候选数组允许为空；必须显式发布 `NO_TARGET`、`MAP_STALE`、`POSE_UNCERTAIN`、`REFERENCE_UNAVAILABLE` 等状态原因，避免电控将“没有消息”误判成“建模已经完成”。候选不附带“可安全飞行”的承诺。

### C. `/mine_uav/model/quality_status`：任务级状态，必须输出

至少包含 `mission_id`、`map_revision`、数据新鲜度、有效待补扫区域数、可生成候选数、质量评估状态，以及是否达到**建模质量完成**条件。`空间探索闭合` 与 `建模质量完成` 必须是两个独立字段；当前控制端的 `model_complete` 不能仅凭前沿消失就代替返程补扫完成。

### D. 可回放的观测证据，必须保留

录包保留逐帧原始或去畸变点云、`/cloud_registered`、`/Odometry`、雷达至机体外参、滤波参数和上述三个新增话题。点云须带时间戳和坐标系；如果密度统计使用的云与 `/cloud_registered` 不同，要写明取样与降采样差异。Livox 驱动可提供逐点时间、反射率、有效标记与线号；这些字段有助于去畸变和回波质量过滤。[Livox ROS 驱动字段说明](https://github.com/Livox-SDK/livox_ros_driver2)

## 4. 与电控侧的联调约定

- **坐标与时钟：**所有区域和候选统一为 `camera_init`；时间戳对应实际扫描时刻，不用发布时刻代替。雷达外参由机械／雷达共同标定，机体目标由雷达侧完成外参换算。
- **地图版本：**候选引用生成它的 `map_revision`；电控收到任务 ID 不符、版本过旧、位姿不可信或超时数据时不得执行。
- **补扫节奏：**电控在去程结束后进入返程补扫阶段，每次只提交一个已验证安全的候选；雷达侧根据新扫描重新统计质量并撤销已补齐的区域。若无安全候选、数据失效或返航余量不足，电控直接返航并记录未补齐区域。
- **职责边界：**雷达侧不直接向 PX4、MAVROS 或 SUPER 发飞行指令；电控侧不重新实现 FOS 或密度统计，只消费雷达侧带版本的结果并做飞行可行性判断。

## 5. 交付和验收样例

1. 交付 ROS1 节点／消息定义、参数文件、启动说明、外参和录包分析脚本；在 RViz 显示 FOS、低密度区域及 NBV 候选。
2. 用已知缺口的点云录包证明：健康区域不会误报；被遮挡区域不会被简单判为零密度；薄弱区域有稳定 ID、范围和可解释原因。
3. 用去程和返程两段录包证明：补扫后目标区域有效密度或可见表面积增加，区域状态随新观测更新；无收益候选被撤销。
4. 用断流、地图重置、外参不一致和过期候选测试证明：输出明确状态，电控不会收到旧地图上的补扫目标。

电控侧将另行验收候选的安全可达性、返程时间与电量预算、SUPER 目标接受确认、异常放弃补扫后的回家行为。
